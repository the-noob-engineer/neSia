# neSia syntax

The neSia syntax takes inspiration from Rust.

```neSia
let name: String = "Dawda borje Kujabi"

fn display_name(arg1: String = "example") -> String {
  return "hello"
}
```

## Current compiler pipeline

The project is structured around a normal compiler pipeline:

```text
source file
  -> ns_lexer
  -> ns_parser
  -> ns_ast
  -> ns_hir
  -> ns_compiler
  -> ns_bytecode
  -> ns_vm
  -> ns_runtime / stdlib
```

### Stage responsibilities

- `ns_lexer`: reads raw source text and emits tokens
- `ns_parser`: groups tokens into expressions, statements, and declarations
- `ns_ast`: stores the parsed tree in a structured form
- `ns_hir`: lowers AST into a more semantic representation
- `ns_compiler`: emits VM-ready bytecode
- `ns_bytecode`: defines opcodes and bytecode layout
- `ns_vm`: executes generated bytecode
- `ns_runtime` / `ns_std`: runtime support and library/runtime helpers

## Current implementation status

The lexer is the stage currently implemented and verified in the repo. The rest of the pipeline is present as crates and project scaffolding, but is not yet fully wired into an end-to-end interpreter.

This means the project is already capable of tokenizing the syntax above and similar examples, while the downstream parser/compiler stages are still being built out.
